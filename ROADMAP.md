# 1,000-Problem Roadmap

## Scope

The target is **1,000 distinct LeetCode problems in total**, not 1,000 per language. The repository language matrix covers 32 languages and query languages. Use suitable languages across the collection and add alternate ports when they provide meaningful practice. Not every language is supported by LeetCode's judge.

## Work phases

1. **Foundation (current):** repository conventions, progress tracking, language policy, and problem templates.
2. **Core patterns:** arrays, strings, hash maps, two pointers, sliding window, stacks, queues, binary search, linked lists.
3. **Trees and graphs:** traversal, BSTs, heaps, union-find, topological sorting, shortest paths.
4. **Advanced patterns:** backtracking, greedy algorithms, dynamic programming, tries, bit manipulation, intervals, mathematics.
5. **Language expansion:** idiomatic ports in the planned language set, including Erlang, R, OCaml, F#, Clojure, Julia, Nim, Zig, and SQL where appropriate.
6. **Consolidation:** revisit difficult problems, add missing language ports, improve tests and explanations.

## Suggested distribution (planning target)

| Difficulty | Target share | Approx. problems |
|---|---:|---:|
| Easy | 30% | 300 |
| Medium | 50% | 500 |
| Hard | 20% | 200 |
| **Total** | **100%** | **1,000** |

This is a planning distribution, not a claim about a fixed official LeetCode list. The actual catalog will be selected and recorded by problem ID and title.

## Language strategy

Use all 19 planned languages across the repository, but do not force every problem into every language. Prioritize broad coverage in Python, C++, Java, JavaScript, and Rust; use the remaining languages for focused ports and language-specific learning.

## Completion gate for each problem

- [ ] Correct LeetCode ID, title, difficulty, and topic recorded
- [ ] Canonical problem README written
- [ ] At least one complete implementation added
- [ ] Edge cases considered and tests run
- [ ] Time and space complexity documented
- [ ] Judge status recorded accurately, if submitted

A problem is not marked complete merely because its folder or README exists.
